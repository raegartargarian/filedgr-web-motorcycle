## Design Context

### Users
Car owners who bring their vehicles to a dealership for service. They access this portal to view their vehicle's complete service history — before/after repair photos, invoices, parts used, and blockchain-verified records. They are non-technical and want clear, visual proof that the work was done properly. Their context: checking service records after a visit, or reviewing history before selling/buying a vehicle.

### Brand Personality
**Premium, Trustworthy, Modern** — like a luxury car brand's official service portal. The interface should feel authoritative and confident without being cold. Every element should reinforce that service records are verified, immutable, and professionally documented.

### Aesthetic Direction
- **Visual tone:** Light & clean — white/light gray backgrounds, generous whitespace, clean card-based layouts. Premium SaaS feel with automotive context.
- **Reference:** Carfax/AutoCheck vehicle history reports — timeline of services, verification badges, clear before/after comparisons, status-driven.
- **Anti-reference:** Cluttered auto repair shop websites, overly technical blockchain UIs, dark/gamer aesthetics.
- **Theme:** Light mode primary. Dark accents only for hero sections or emphasis areas.
- **Color direction:** Keep the blue-600 as primary action color. Green for "verified/complete" status. Slate neutrals for structure. Subtle gradients for premium feel, not garish.
- **Typography:** Neue Haas Grotesk for headings (premium feel), Inter for body (readability). Large, confident headings. Comfortable line heights.

### Design Principles
1. **Proof over promise** — Every service record should visually prove work was done. Before/after photos front and center, not buried in tabs. Verification badges prominent.
2. **Scan, then dive** — Vehicle list shows key info at a glance (name, date, status, stream count). Detail pages let users drill into specifics. No walls of text.
3. **Trust through transparency** — Blockchain verification should be visible but not overwhelming. Subtle "verified" indicators, transaction links available but not dominant.
4. **Progressive disclosure** — Show the most important information first (vehicle overview, latest service). Expandable sections for deeper detail (individual files, parts lists, transaction hashes).
5. **Premium simplicity** — Every pixel should feel intentional. Generous spacing, consistent alignment, refined animations. Less is more — if an element doesn't build trust or clarity, remove it.

### Component Patterns
- **Cards:** White background, subtle border (gray-200), rounded-xl, shadow-sm. Hover: shadow-md transition.
- **Status badges:** Soft colored backgrounds with matching text (green for complete, blue for in-progress, amber for pending).
- **Buttons:** Primary = blue-600 filled. Secondary = outline with gray border. Ghost for navigation actions.
- **Animations:** Subtle fade-in on page load (Framer Motion). No bouncing or excessive movement. Smooth transitions (300ms ease).
- **Icons:** Lucide React, 20px default size, gray-500 for decorative, blue-600 for interactive.
- **Spacing:** 24px between major sections, 16px between related elements, 8px between tightly coupled items.

### Tech Stack
- React 18 + TypeScript + Vite
- Tailwind CSS 3.4 + SCSS
- Framer Motion for animations
- Radix UI primitives (tabs, dropdown, progress)
- Shadcn/ui components (button, card, badge, tabs, skeleton, separator, progress, scroll-area, carousel, dropdown-menu)
- Lucide React icons
- Redux Toolkit + Redux Saga
- JSZip for repair record extraction
- Recharts for data visualization
